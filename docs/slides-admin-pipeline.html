Admin Pipeline & Governance

Satu konsol untuk memutuskan apa yang boleh dijalankan AI — seperti console admin Claude: mode, tool, memori, artifact, feedback 👍/👎, RAG — dan semua langkah terekord di Mechanistic Interpreter yang selalu aktif.

Kenapa perlu governance?

  • Tool eksternal (browsing) & generatif (gambar, PPT) = permukaan risiko.
  • Perilaku model perlu bisa diarahkan tanpa redeploy (memori + feedback).
  • Keluaran biner harus terregistry & bisa diaudit.
  • User eksternal = percaya harus dibuktikan dengan jejak.

Prinsip desain

  • Server-side enforcement — UI hanya menyembunyikan; API menolak.
  • Interpreter always-on — dikunci di kode, bukan preferensi.
  • Satu sumber kebijakan (governance.py) untuk semua gate.
  • Semua fitur jalan offline (provider mock / HF lokal) supaya layak demo.

Tool yang bisa dinyalakan/dimatikan

  • web_search, fetch_url — bukti web (wajib sitasi).
  • create_diagram, calculator — generatif/deterministik.
  • generate_image, generate_ppt — mode baru.
  • save_memory — AI menulis memori (dapat dimatikan terpisah).

Dua lapis penolakan

  • Tidak diiklankan: schema tool tidak dikirim ke model → kebanyakan model tidak akan memanggilnya.
  • Tetap ditolak: bila model meng-hallusinate nama tool, loop menolak mengeksekusi, merecord event policy, dan memberi tahu model untuk lanjut tanpa tool itu.

Dua generator gambar, jujur soal asal

  • poster-v1 (offline) — fallback deterministik: poster SVG dari hash prompt (gradient + geometri + teks). Selalu berhasil, cocok untuk demo tanpa jaringan.

  • artifacts.max_artifacts — registry dipangkas FIFO.

  • PPTX dibangun python-pptx dari outline terstruktur model → hasil deterministik & bisa dibaca ulang (outline di meta).
  • Hapus artifact = file + row ikut terhapus.

  • Panel RAG menampilkan stage berjalan & jumlah chunk/halaman.
  • Status & timings tersimpan per dokumen (audit).

Kenapa embedding hashing?

  • Deterministik — index tetap valid kapan pun di-query.
  • Tanpa server/model — RAG jalan di CPU paling lemah pun.
  • Retrieval leksikal yang jujur (cosine); antarmuka Embedder siap ditukar sentence-transformers/API tanpa mengubah pipeline.
  • Chunk tidak memotong halaman → sitasi selalu sebut halaman benar.

8 · Mechanistic Interpreter — selalu jalan, semuanya terecord

Yang direcord (SQLite trace_events)

  • meta — provider, model, sampling, mode, snapshot policy, daftar memori, interpreter flags.
  • prompt — system prompt final (memori + pedoman + arah mode) & messages persis.
  • llm_request/llm_response — payload, thinking, tool_calls, durasi.
  • thinking/delta/logprobs/usage — token-per-token.
  • tool_call/tool_result — argumen mentah + payload + status + durasi.
  • Baru: rag_stage, rag_retrieve, artifact, policy (keputusan governance).

Mengapa “selalu-on”?

  • Janji produk: setiap jawaban bisa ditanya kenapa.
  • interpreter.always_on dikunci True di governance.policy() — PUT dengan false diabaikan.
  • Admin tetap mengatur detail: record_logprobs, record_tool_payloads.
  • UI: tab Log (timeline), LLM, Prompt, Tokens, Metrics, Sources — live saat run & replay dari riwayat.
Event governance juga masuk log: bila tool diblokir admin, user bisa melihat baris policy · tool_blocked — transparansi berlaku juga untuk kebijakan itu sendiri.

12 · Menjalankan & checklist produksi

Menjalankan lokal

# backend (mode demo offline)
cd backend
pip install -r requirements.txt
ASK_PROVIDER=mock uvicorn app.main:app --port 8000

# frontend
cd frontend && npm ci && npm run dev
# → http://localhost:3000 · /admin

# tes
pytest tests -q          # backend
npm run test && npm run typecheck  # frontend

Sebelum dipublish ke user

  • Set ASK_ADMIN_TOKEN (wajib di deployment publik).
  • Review tab Pipeline: matikan mode/tool yang belum diinginkan.
  • Isi memori dasar (tone, batasan produk).
  • Aktifkan feedback + auto-guidance, pantau rasio 👍/👎.
  • Upload dokumen RAG resmi (batas ukuran sudah di policy).
  • Interpreter: biarkan selalu-on — itu fitur auditnya.
Batas jujur: single-node SQLite (belum multi-tenant), embedding leksikal (bukan semantic model), admin console satu peran (belum granular RBAC). Semua sudah disiapkan antarmukanya untuk ditukar ke versi yang lebih besar.
ringkasan

Pipeline yang layak publish = governance + transparansi + umpan balik

  • Satu policy di server mengatur 6 mode & 7 tool — UI dan API tunduk sama.
  • Memori + feedback = dua jalur mengubah perilaku tanpa sentuh kode; asal-usul pedoman selalu terlihat.
  • Artifact (gambar, PPT) teregistry, ter-label generator, bisa diaudit.
  • RAG upload-and-go: parsing → chunking → embedding → retrieval → generate, semua tahap terlihat.
  • Interpreter selalu-on — semua event, termasuk keputusan policy, terecord & bisa di-replay.
  • Diuji: 185+ tes backend + 161 tes frontend, termasuk gate governance & pipeline RAG end-to-end.
