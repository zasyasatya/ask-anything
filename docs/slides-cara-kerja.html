2 · Prinsip Desain

Transparansi radikan

  • Setiap satuan kerja (token thinking, tool call, hasil tool, logprob, usage) adalah event pertama-kelas.
  • Event di-stream live dan dipersist → bisa di-replay seperti "flight recorder".

Provider-agnostic

  • Satu protokol (OpenAI chat-completions streaming) dipakai untuk HF-lokal, OpenAI, dan mock.
  • llama.cpp, vLLM, LM Studio, OpenAI — semua berbicara protokol ini.

Degradasi graceful

  • Tool gagal (mis. offline) → error jadi data bagi model, bukan crash.
  • Tanpa server LLM → UI menawarkan mode mock; backend tetap sehat.

Schema-driven tools

  • Tool dideklarasikan sebagai JSON-Schema → otomatis jadi tools[] OpenAI & dokumentasi.
  • Output diagram divalidasi server-side sebelum dirender.

3 · Lifecycle Satu Request

POST /api/chat {message, conversation_id?}
 │
 ├─ 1. pastikan conversation (buat baru + judul = potongan pesan)
 ├─ 2. muat history → konversi ke message OpenAI
 ├─ 3. spawn task agent; event masuk asyncio.Queue
 ├─ 4. StreamingResponse(text/event-stream) menarik queue → data: {...}\n\n
 │
 │   event: start → meta → [thinking|delta|logprobs|tool_call|tool_result|usage]* → done → agent_done
 │
 └─ 5. persist messages + trace; touch updated_at
  • Backpressure aman: queue memisahkan produksi (agent) dan konsumsi (SSE generator).
  • Jika klien putus, task di-cancel di finally — tidak ada zombie loop.

4 · Algoritma Agent Loop

messages ← history + user
for step in 1..max_steps:                     # default 6, cegah loop liar
    events ← provider.stream(messages, tool_schemas)
    kumpulkan: thinking, delta, logprobs, usage
    if ada tool_calls:
        simpan pesan assistant(tool_calls)
        for each call:  result ← tool.run(args)   # timeout 30 dtk
            emit tool_call / tool_result; persist
            messages += assistant_toolcalls + role:tool
        messages += hint "tulis jawaban final sekarang"
        continue                                # langkah berikutnya
    else: break  → jawaban final terkumpul
emit done{answer, usage, latency}; persist assistant
  • ReAct-style: reason → act (tool) → observe → answer, dengan batas langkah eksplisit.
  • Argumen tool diakumulasi dari chunk JSON parsial (llama.cpp mengirim argument dicicil).

5 · Protokol Message (OpenAI-compatible)

[ {role:system,  content: SYSTEM_PROMPT}          # identitas + aturan tool + mermaid
, {role:user,    content: "..."}
, {role:assistant, content:null, tool_calls:[{id,type:"function",
     function:{name:"web_search", arguments:"{\"query\":...}"}}]}
, {role:tool, tool_call_id:"call_1", content:"{...hasil JSON...}"}
, {role:system, content:"Tool results appended... tulis jawaban final."} ]
  • History internal disimpan dengan role khusus (assistant_toolcalls, tool) lalu dipetakan ke bentuk di atas — UI bisa menyembunyikan detail, LLM tetap mendapat konteks utuh.
  • Konteks dibatasi max_context_messages agar muat di laptop.

6 · Wire Format & Parsing SSE

data: {"choices":[{"delta":{"content":"<think>planning..."}}]}
data: {"choices":[{"delta":{"content":"...</think>"},"logprobs":{
        "content":[{"token":"Final","logprob":-0.12,"top_logprobs":[...]}}]}]}
data: {"choices":[{"delta":{"tool_calls":[{"index":0,"function":{"arguments":"{\"qu"}}]}}]}
data: {"choices":[{"finish_reason":"tool_calls"}]}
data: {"usage":{"prompt_tokens":150,...},"choices":[]}
data: [DONE]
  • _ThinkParser: state-machine 2 mode (answer/thinking) dengan suffix-hold, tahan tag <think> yang terbelah antar chunk.
  • tool_calls diakumulasi per index (id/name/arguments dicicil) → di-parse JSON di akhir turn.
  • logprobs per token → tab Tokens (prob = e^logprob + top alternatif).
  • reasoning_content (format server lain) juga didukung.

 │         snippet = sibling <td> / <tr> berikutnya

 ├─ httpx + UA browser, follow redirect, timeout

11 · Streaming ke UI

fetch("/api/chat", POST) → res.body.getReader()
 loop: buffer += decode(chunk)
   potong per "\n\n" → parse "data: " → dispatch:
     delta      → tambahkan jawaban (Markdown live + Mermaid saat fence lengkap)
     thinking   → kotak 💭
     tool_call  → chip animasi "web_search…"
     tool_result→ chip ✓ + summary
     logprobs   → tab Tokens
 selesai → muat ulang conversation (sumber kebenaran = DB)
  • State React di-update per event; auto-scroll; kursor blink saat stream.
  • Setelah agent_done, UI me-reload dari API → konsisten walau stream terputus di tengah.

14 · Emulator = Metodologi Kunci

Masalah

  • CI/sandbox tanpa GPU & tanpa internet eksternal.
  • Model asli nondeterministik → assert rapuh.

Solusi: fake_llama_server

  • Server HTTP terpisah (port 8081) yang meniru perilaku model agentic: emit <think>, memanggil tool, mengirim argument dicicil, logprobs, usage, [DONE].
  • Kode produksi (provider HTTP, agent loop, tools, SSE, UI) berjalan tanpa diubah.
  • Deterministik → pipeline CI-stable, sekaligus mode demo pengguna.

17 · Batasan & Roadmap

Batasan saat ini

  • Logprobs hanya bila provider mendukung (llama.cpp: ya).
  • SQLite single-node; belum multi-user auth.
  • DDG scraping bergantung struktur halaman publik.

Roadmap

  • Sandbox eksekusi kode (python_exec) dengan rlimit.
  • Attention/entropy view di interpreter (bila backend mengekspose).
  • Multi-agent delegate + memori jangka panjang.
  • Export percakapan + trace ke JSON/Markdown.
ringkasan

Agent = loop ReAct + event-first transparency

  • Satu protokol OpenAI-streaming → HF lokal, OpenAI, mock.
  • Setiap satuan kerja = event: di-stream live, dipersist, bisa di-replay.
  • Tools schema-driven; diagram & browsing tervalidasi dan graceful.
  • Testing: mock hanya di batas jaringan; emulator wire-format untuk E2E.
  • Satu perintah jalan di laptop: python3 run.py --demo / --gguf.
